# 07 · 共创 brief 核查表

品牌（腾势/比亚迪系）的共创 brief 格式高度稳定。这张表是"交片前 3 分钟"的核对清单，
每一条都对应过被判无效或不计分的真实原因。

---

## 一、开工前先确认（决定要不要做）

| # | 核对点 | 在哪看 | 漏了会怎样 |
|---|---|---|---|
| 1 | **发布平台** | brief「传播平台」段 | 少发平台 = 少一半基础分；有的活动只算抖音+视频号 |
| 2 | 发布窗口 | 「传播时间」 | 过期发布不计分（常见是"今天最后一天"） |
| 3 | 时长下限 | >15s / >20s / >30s | 差 1 秒也不给分 |
| 4 | 文案字数 | >15 字 / >20 字 | 同上 |
| 5 | **必带话题** | 是否标「必带」；是"六选二"还是全带 | 少带/多带都可能判无效 |
| 6 | 指定植入话术 | 如「建议标题植入：科技豪华成就宽适人生」 | 漏了直接影响判定 |
| 7 | 口播要求 | 「需有口播（可 AI 配音）或真人出镜」 | AI 配音可以，纯字幕不行 |
| 8 | 封面要求 | 「封面需有标题、字体显示完整」 | 单列一条，最容易漏 |
| 9 | 拉踩红线 | 「客观表述，不拉踩任何品牌」 | 出现对比即违规 |
| 10 | 一稿多投 | 「不能与社区话题同时参加」 | 同时参加两边都无效 |
| 11 | 回传时间 + 链接 | 末尾，常是二维码 | 错过 = 白干 |

回传二维码用脚本解，别手抄：

```python
import cv2, numpy as np
img = cv2.imdecode(np.fromfile("qr.png", dtype=np.uint8), cv2.IMREAD_GRAYSCALE)
img = cv2.copyMakeBorder(img, 60, 60, 60, 60, cv2.BORDER_CONSTANT, value=255)
img = cv2.resize(img, None, fx=5, fy=5, interpolation=cv2.INTER_NEAREST)
print(cv2.QRCodeDetector().detectAndDecode(img)[0])
```
> 小图直接识别经常失败，**必须加白边 + 放大 5 倍**。

## 二、成片自查（发布前）

- [ ] 时长 ≥ 下限，且**不是靠片尾黑屏/静音凑的**（`autopilot qc` 会拦静音）
- [ ] 声画同步：口型、动作与配音对得上
- [ ] 片尾没有长时间黑屏、没有静音段
- [ ] 字幕无错别字，不超出安全区（底部留 ≥250px 给抖音 UI）
- [ ] 数字全部有出处：价格/续航/加速/尺寸与 brief 一致，工况（CLTC 等）写清楚
- [ ] 没有"最/第一/唯一"类极限词（品牌官方话术除外，且要能指回素材）
- [ ] 素材清晰度够：不用录屏、不用带水印的二次压缩件
- [ ] 封面：有标题、字完整、3:4 竖版、不是片头黑帧

## 三、发布后（30 秒）

- [ ] 两个平台都显示"已发布"（截图核验，别只信接口返回）
- [ ] 抖音封面不是黑块（自动封面常取到片头淡入帧）
- [ ] 话题齐全；描述第一句能抓人（抖音列表显示的是描述开头）
- [ ] 记录链接，按窗口回传问卷

---

## 四、奖励口径（腾势系活动为例）

- **基础**：单平台 1000（部分活动 500），双平台 2000，三平台 2000+
- **爆款**：单平台 5 万播 + 500 互动 → 5000；双/三平台综合 10 万 + 1000 互动 → 10000；
  20 万 + 1500 → 15000
- **不叠加**：爆款与基础二选一，按高的发；单人 15000 封顶
- **抢鲜奖**（部分活动）：发布会结束后 1 小时内产出并送审，获官方投流且播放 >10 万再加 2000
  —— **只有发布会当天有效**

> 结论：先保"合规发布"，再谈爆款。少一个平台、少一个话题，直接掉出计分范围。
